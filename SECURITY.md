# Security policy

Only the current default branch receives security fixes; there are no supported production releases yet. The local prototype must remain bound to numeric loopback. Source text is untrusted input, and draft output always requires review.

Report vulnerabilities through this repository's **Security → Advisories → Report a vulnerability** private reporting option after the maintainer enables it. Do not disclose exploitable details, customer data, source messages, credentials or raw runs in a public issue. If private reporting is unavailable, open a minimal issue asking the maintainer to enable it without including the vulnerability details or sensitive attachments.

Include a synthetic reproduction, affected commit, relevant versions, impact and expected behavior. Avoid real records. Maintainers will coordinate a fix and disclosure; no guaranteed response time is promised. For accidentally published credentials, the owner should revoke them immediately and coordinate history cleanup privately.
